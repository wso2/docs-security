### OVERVIEW
OAuth2 token revocation behavior mismatch when allowed_scopes is enabled.


### DESCRIPTION
When the allowed_scopes configuration is enabled, an access token that was introspected immediately before a revocation request may be returned again to the client after revocation. This behavior is observed until the relevant cache entry is cleared.


### IMPACT
A revoked access token may be re-issued to the client during the cache lifetime. Based on current behavior, the re-issued token is not treated as valid for API authorization. However, until the cache is cleared, affected users may be unable to obtain a new valid access token, which can disrupt authentication flows.


### SOLUTION

#### Community Users (Open Source)
Apply the relevant fixes to your product using the public fix(es) provided below.

* [https://github.com/wso2-extensions/identity-inbound-auth-oauth/pull/3303](https://github.com/wso2-extensions/identity-inbound-auth-oauth/pull/3303)

If applying the fix or update is not feasible, migrate to the latest unaffected version of the respective WSO2 product(s).


#### Support Subscription Holders

Update your product to the specified update level or a higher update level to apply the fix.
